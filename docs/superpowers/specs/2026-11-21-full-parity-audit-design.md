## 1. الغرض ومعيار النجاح

غرض التدقيق هو **اكتشاف أي انحراف حقيقي عن سلوك المشروع القديم قبل الإطلاق**، لا إعادة كتابة المواصفات ولا تحسين الكود. الناتج تقريرُ `findings` مرتّبٌ بالخطورة، لكلٍّ منه دليلٌ من الطرفين، وأثرٌ، وتوصيةٌ، وشريحةُ إصلاحٌ مقترحة.

معيار النجاح:

1. كل وحدة تدقيق تُعاد إثباتها **من الصفر** — لا يُقبل حكمٌ سابق لم يُعَد تتبّعه إلى كود/اختبار/فحص فعلي.
2. لا يوجد `finding` بلا `old_ref` و`new_ref` و`method` صريحة.
3. الانحرافات الموثّقة (`Defer` · `Drop` · F-125 الجزئي) تُصنَّف `documented-deviation` وتظهر في التقرير، لكنها لا تُحتسب عيبًا جديدًا.
4. بوابة `pnpm audit:check` تمرّ، ومصفوفتا `parity.md` و`feature-parity.md` تبقيان محدَّثتين.
5. كل شاشة تُفحَص في **المتصفّح المدمج** بـ `snapshot` + `console` + `screenshot`، بصفر مفاتيح خامّة وصفر أخطاء console.

## 5. التصنيف والحكم

### 5-1. الأحكام (Verdicts)

| الحكم | المعنى |
|---|---|
| `match` | السلوك الحالي يطابق القديم دلاليًّا، بالدليل |
| `documented-deviation` | انحرافٌ معلنٌ وموثّق (`Defer`/`Drop`/F-125/حدود مسجَّلة) |
| `undocumented-deviation` | انحرافٌ بلا مبرّر موثّق — يُعدّ finding |
| `unverifiable` | لا يمكن إثباته بالأدوات المتاحة — يُعرض في قسم منفصل |

### 5-2. الشدّة (Severity)

| الشدة | المعنى |
|---|---|
| `blocker` | فقدان بيانات، كسر أمان، أو عدم إمكانية الإطلاق |
| `high` | انحراف سلوكي مؤثّر يلمس مسارًا أساسيًا |
| `medium` | انحراف في حالة حافة أو رسالة أو تنسيق |
| `low` | تفصيل تحسيني لا يمنع الإطلاق |
| `info` | ملاحظة توثيقية |

### 5-3.قاعدة الإغلاق

لا يُغلق finding إلا بثلاثة أشياء: `old_ref` + `new_ref` + `method` مع نتيجة مُثبَتة. أي خلاف بين المسارات يُحال إلى **مراجع عدائي مستقل** (deepseek، جلسة منفصلة، للقراءة فقط) يفصل بالأدلة؛ ثم يعرض على المستخدم للقرار النهائي. لا يُعدّ «مطابقًا» ما مرّ بـ `tsc` أو `clippy` وحدهما — هذا درسٌ من ثلاثة عيوب اكتشفها المتصفّح سابقًا.

## 6. المخرجات والبوابات

### 6-1.المخرجات

1. `docs/spec/audit-ledger.json` — الدفتر الكامل.
2. `docs/spec/audit-findings.md` — **مولّد**، جدولٌ لكل بُعد + جدول findings مرتّب بالخطورة.
3. `docs/spec/audit-report.md` — ملخّص عربي: ما طابق · ما انحرف بعذر · ما انحرف بلا عذر · ما تعذّر تحقّقه · التوصيات.
4. قسم «ما لم أتحقق منه» صريح في التقرير، مع لقطة شاشة وسجل `console` لكل فحص واجهة.

كل `finding` في التقرير يحمل: `id` · `dimension` · الأثر · `old_ref` · `new_ref` · `method` · `severity` · التوصية · الشريحة المقترحة.

### 6-2.البوابات

```text
node scripts/build-audit-report.mjs --check   # الدفتر مكتمل ومتسق والمخرَج محدَّث
pnpm audit:check                              # نفس الفحص عبر pnpm
node scripts/build-parity-matrix.mjs --check  # لم تتأثر مصفوفة التتبّع
node scripts/build-feature-parity.mjs --check # لم تتأثر مصفوفة الميزات
node scripts/check-i18n.mjs                   # صفر أخطاء
browser: snapshot + console + screenshot لكل شاشة
```

التدقيق للقراءة فقط؛ لا تُغيَّر مصادر التطبيق، ولا يُغيَّر `feature-parity.json` دون موافقة المستخدم وخط أنابيب PR/CI.
