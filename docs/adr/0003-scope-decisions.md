# ADR 0003 — قرارات النطاق (Scope Decisions)

- **الحالة:** مقبول
- **التاريخ:** 2026-10-15
- **يخلف:** لا شيء · **يُشار إليه من:** `docs/spec/features.md` · `docs/spec/decision-sheet.md`

## السياق

المشروع الجديد (ModManager) يُعيد كتابة تطبيق بايثون/PySide6 مكتمل (0.14.0rc1) بـ Rust + Tauri 2 + React.
`AGENTS.md` §14 يفرض أن يُنقَل السلوك لا الكود، وأن يحسم صاحب المشروع كل ميزة Keep/Drop/Defer قبل M1.
استُخرجت المواصفات في `docs/spec/` (21 وثيقة، 181 ميزة)، وأحسم صاحب المشروع القرارات التالية.

## القرارات

### 1. الترخيص مُلغى نهائياً — `F-175` = Drop

التطبيق مجاني. **لا نظام ترخيص، ولا بصمة جهاز، ولا نافذة تفعيل، ولا تبعية `cryptography`.**

أُلغيت **16 مرحلة و14 وثيقة** في المشروع القديم لمجرد بوابة تنافس عميلاً على مجانية. لا نُعيد أي جزء منها.
لمجرد بوابة تنافس عميلاً على مجانية. لا نُعيد أي جزء منها.
**لا `license-notes.md`** — السلوك القديم موثّق في `features.md` وسطر واحد في `decision-sheet.md` §D.

### 2. CurseForge خارج v1 — في M3 بمفتاح المستخدم

**v1 = مزوّد Modrinth وحده.** CurseForge مؤجَّلة إلى M3، وتُدخل **المستخدم** مفتاح الـAPI في الإعدادات.
لا وكيل، ولا مفتاح مضمَّن في التوزيع.

⚠ **لا مرجع سلوكي للوراثة:** CurseForge **غير موجودة إطلاقاً** في المشروع القديم
(لا ملف، لا في أي فرع، ولا في تاريخ git — انظر `docs/spec/behaviors/gap-analysis-notes.md` §12.6).
أي تنفيذ لها **تصميم جديد** لا نقل.

### 3. بيانات التطبيق القديم: زرّ اختياري في M4

**لا قراءة تلقائية ولا ترحيل صامت.** زرّ في M4 يقرأ نسخة `.modrinth_bulk_downloader`
وينشئ نسخاً جديدة، **مع نسخة احتياطية قبل أي تعديل**. أُضيف كـ`F-181` بقرار `Keep` ومرحلة `later`.

### 4. `User-Agent`: ثابت واحد مؤقت مع بوابة إصدار

قيمة واحدة قابلة للضبط في `core`، قيمتها المؤقتة:

```
ModManager/0.1.0-dev (dev build)
```

**ويُشترط** أن **يفشل بناء الإصدار النهائي** ما دامت القيمة المؤقتة في مكانها — استبدالها بقيمة نهائية
تحتوي وسيلة تواصل، كما يفرض `AGENTS.md` §5.11. **ولا طلبات شبكة حقيقية متكرّرة بالقيمة المؤقتة**;
اختبارات `wiremock` فقط.

### 5. تفعيل المود = إعادة تسمية الملف، بلا استثناء

`.jar.disabled` **مصدر الحقيقة الوحيد**. أي عمود `enabled` في القاعدة **ذاكرة مشتقّة** تُحسب من اسم
الملف وقت المسح. `AGENTS.md` §5.12 غير قابل للتفاوض.

### 6. `ownership_policy` أُلغي — عمود `source`

عمود `ownership_policy` القديم **لا يقرأه أي مسار تعديل** (تحقّق مباشر). حُذف، وتُدمج فائدته في:

```rust
enum Source { Managed, Manual, Adopted }
```

`Adopted` تعني «جالبها من مود باك مُثبَّت» — وهي مطابقة لما اقترحته وثيقة الفجوات نفسها
(`InstalledContent` يفصل `pack_owned` / `user_added` / `external` / `managed`).

### 7. تصدير `.mrpack` مع overrides في M3 — `F-082`

يُ-export `overrides/` مع اختيار مجلدات من المستخدم، **مع استبعاد ما قد يحوي أسراراً**
(نفس قائمة الاستبعاد المستعملة في `profile_export.py:34-87`).

### 8. توزيع المراحل — v1 = M1 + M2

| المرحلة | العدد |
|---|---|
| M1 النواة والأمان | 77 |
| M2 الواجهة | 39 |
| M3 التوسّع (CurseForge · المود باكات · المودات اليدوية) | 44 |
| خارج v1 | 8 |
| Drop | 13 |
| **المجموع** | **181** |

**v1 = 116 ميزة (64%).**

## النتائج

**إيجابية:** 13 Drop تحذف أكبر بند في المشروع القديم (الترخيص) و20 مرحلة تغليف؛
16 مسجّل قرار واحد يحسمها؛ v1 محدود بـ116 ميزة قابلة للاختبار.

**سلبية:** 65 ميزة خارج v1، منها CurseForge كاملةً — وهذا أكبر مصدر خطر جدول زمني في M3،
لأنه **بلا أي مرجع سلوكي**.

## alternativas مرفوضة

| البديل | لماذا مرفوض |
|---|---|
| ترخيص مبسَّط بلا بصمة | يبقى تكلفة صفر فائدة |
| تضمين مفتاح CurseForge في التوزيع | يخالف `decision-sheet.md` §E-1 ويحتاج وسيطاً |
| قراءة تلقائية لبيانات القديم | ترحيل صامت بلا رضا المستخدم |
| قيمة `User-Agent` نهائية الآن | لا رابط مستودع بعد؛ والمؤقتة محروسة ببوابة |
