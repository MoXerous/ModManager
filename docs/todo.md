## تعريفُ الإنجاز لكل مهمة

```
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace   # يُعيدُ توليد src/bindings أيضًا — «بِيَنَّ ملفَّاته المولَّدةَ»
pnpm build
```

أوّلُ نتيجة **فاشلة** تُوقِفُ المهمة. و«اختبارٌ لم يُنفَّذ» ليس نجاحًا. `.github/workflows/ci.yml` يشغِّلُ الأوامرَ نفسَها على ubuntu-22.04 وwindows-latest، ونجاحُ CI هو الدليلُ الخامِ على اجتيازِ البوّابة.

## قيودٌ دائمة في هذه البيئة

- RAM حرّة منخفضة (~2 GB): البناءُ يحتاج `CARGO_PROFILE_DEV_DEBUG=0` مع تعطيلِ `incremental`
- قرص C: شبه ممتلئ (2.2 GB): `CARGO_TARGET_DIR` على `F:` — هدفُ البناء يجبُ أن يكونَ على `F:`
- WSL بلا `sudo`: **CI هو بوابةُ لينكس**، لا الجهازُ المحلّي
- **يُمنعُ تشغيلُ بنائَينِ cargo معًا**: قتلُ المُجمِّع أثناء عملٍ يترِكُ بياناتَ وصفٍ مقطوعَةً تُقرأُ كأنّها «invalid metadata files» — ثم على الوفاةِ حذفُ الهدف وتنظيفُ الشوائب قبل أيّ بناءٍ جديد.
